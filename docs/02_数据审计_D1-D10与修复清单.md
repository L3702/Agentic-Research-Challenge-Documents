## D3｜空季度被静默算成 0，末期季度不完整（P0）

**现象 1**：`ret` 恰好等于 0.0 的行有 **21 行，全部在 1999Q4**。
原因：`(1 + NaN).prod() - 1`，pandas 的 `prod` 默认跳过 NaN → 空季度算出 `1 - 1 = 0`。

**现象 2**：末期 `2026Q4` 只含 **24 个交易日**（2026-10-08 至 2026-11-11），完整季度约 60 个。

**为什么致命**：**你的"缺失率 0%"是 bug 造出来的假象**——空季度不是"没有数据"，而是"被算成 0 收益"。这比缺失更危险，因为 0 会进入均值、进入超额收益、进入回归，而且看不出来。这是本审计里最像"隐藏地雷"的一条。

**修复代码（pandas 3.x 安全版）**：

```python
import numpy as np, pandas as pd

def quarter_returns(close: pd.Series) -> pd.Series:
    """把日收盘价聚合成季度收益；空季度返回 NaN，不完整季度丢弃。"""
    close = close.sort_index()
    r = close.pct_change()

    g = r.groupby(r.index.to_period("Q"))
    out = pd.DataFrame({
        "n": g.size(),
        "last_day": g.apply(lambda s: s.index.max()),
        "ret": g.apply(lambda s: (1 + s.dropna()).prod() - 1 if s.notna().any() else np.nan),
    })
    qend = out.index.to_timestamp(how="end").normalize()
    # 完整季度：至少 40 个交易日，且最后一个交易日距季度末不超过 10 天
    keep = (out["n"] >= 40) & ((qend - out["last_day"].dt.normalize()).dt.days <= 10)
    out = out.loc[keep, ["ret"]]
    out.index.name = "quarter"
    out["quarter"] = out.index.astype(str)      # -> "2014Q1"
    return out
```

**验收**：新面板中 `(ret == 0).sum() == 0`；`2026Q4` 不出现在面板里。

## D4｜102/102 期报告都滞后一期发布，现有面板零对齐（P0）

**现象**：所有报告都在**报告期结束后的下一个季度**发布（gap 分布 `{1: 102}`），发布月份集中在 2/5/8/11 月。

**例**：2026Q1 报告，**2026-05-11** 发布。

**为什么致命**：把"2026Q1 报告情绪"和"2026Q1 行业收益（1–3 月）"放同一行，等于**用 5 月才知道的信息解释 1–3 月的收益**。这是前视偏差（look-ahead bias），审稿人第一眼就会指出来，而且它会让结果**虚假地显著**（因为报告里的宏观数据确实"解释"了已经发生的行情）。

**修复**：建一张事件对齐表 `event_map.csv`：

```python
cal = pd.DatetimeIndex(sorted(trading_days))          # 交易日历（见 D10）
pos = cal.searchsorted(pd.Timestamp(pub_date), side="left")
t0 = cal[pos]                                        # 发布后第一个交易日
t1 = cal[pos + 1]; t5 = cal[pos + 5]; t10 = cal[pos + 10]
```

| period | pub_date | t0 | t1 | t5 | t10 |
|---|---|---|---|---|---|
| 2026Q1 | 2026-05-11 | 2026-05-11 | 2026-05-12 | 2026-05-18 | 2026-05-25 |

**同时要决定**：季度面板里，`2026Q1` 的情绪应该挂到 **2026Q2** 的收益上（发布后第一个完整季度），而不是 2026Q1。

**验收**：`event_map` 102 行；每行 `t0 > pub_date` 或 `t0 == pub_date`（当日发布当日可交易）。

## D5｜`quarter` 是字符串时间戳，排序是错的（P1）

**现象**：`quarter` 的值是 `2000/3/31 0:00` 这种字符串。

**证据**：字典序排序结果 `['1999/12/31', '2000/12/31', '2000/3/31', '2000/6/30']` → **12 月排在 3 月前面**（因为字符 `1` < `3`）。

**为什么严重**：`sort_values("quarter")` 不会报错，但从此所有**滞后项、滚动窗口、时间趋势**全部错位。又一颗静默地雷。

**修复**：`quarter` 统一用 `PeriodIndex` 或 `"YYYYQn"` 字符串；所有时间运算先用 period 类型：

```python
df["q"] = pd.PeriodIndex(df["quarter"], freq="Q")   # 只在库内部用
df = df.sort_values(["industry", "q"])
df["ret_lag1"] = df.groupby("industry")["ret"].shift(1)   # 现在才是对的
df["quarter"] = df["q"].astype(str)                        # 导出时再转字符串
```

**验收**：`df.quarter.drop_duplicates().sort_values().head(3)` 得到 `1999Q4, 2000Q1, 2000Q2`。

## D6｜超额收益的基准随样本构成漂移（P1）

**现象**：`mkt_ret` = **当期样本内**所有行业的等权平均。参与计算的行业数在 **21–34** 之间变化。

**证据**：自动检查 C9；且每季 `ret_ex` 之和恒为 0（机械约束，1.75e-15）。

**为什么严重**：基准本身在变，"超额"的含义就不稳定。2014 年前后基准的成分变了，行业超额收益的截面分布会跟着跳。

**修复**：二选一
1. **固定篮子**：始终用同一组行业（即 D2 选定的 28 个）算等权基准；
2. **外部宽基**：用中证全指或沪深 300（更规范，需多抓一份数据）。

**验收**：`panel.groupby("quarter").industry.nunique().nunique() == 1`。

# 附：这次审计最大的方法论收获

三条"静默错误"（D3 / D5 / D7）有一个共同点：**程序不报错，结果却是错的**。

> **缺失率 0% 不等于数据干净。**
> **排序不报错不等于顺序对。**
> **窗口算出来不是空不等于窗口里有价格。**

这三句话建议抄在团队白板上。它们比任何模型都值钱。
