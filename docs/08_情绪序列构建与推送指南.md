## 二、这个脚本做什么

```
102 份 PDF
   │  ① pypdf 抽文字（自动选后端）
   ▼
清洗（去页眉页码、去掉中文字间空格、丢掉乱码行）
   │  ② 按"货币政策趋势 / 预测与政策建议 / 下一阶段…"切 P 段
   ▼
R 段（回顾）  +  P 段（政策指引）
   │  ③ 情感单元法打分（分句 + 词典 + 否定词翻转）
   ▼
data/processed/sentiment.csv
```

**输出字段**：

| 字段 | 含义 |
|---|---|
| `period` | 报告期，如 `2020Q1` |
| `pub_date` | 发布日期（从 mpr_meta 带过来） |
| `chars` / `chars_R` / `chars_P` | 全篇 / R 段 / P 段的汉字数 |
| `pos_R, neg_R, pos_P, neg_P` | 两段的积极词、消极词计数（否定词已翻转） |
| `tone_R, tone_P, tone_all` | 情绪 = (正 − 负) / (正 + 负)，范围 −1 ~ +1 |
| `z_tone_R, z_tone_P` | 标准化后的情绪（回归直接用这个，系数好解释） |
| `status` | `ok` / `no_heading` / `tail_only` / 报错信息 |
| `anchor` | 实际用哪个标题切的 P 段（方便你复核） |

**为什么分两段**：姜富伟（2021）的结论是"只有政策指引段显著、宏观回顾段不显著"。我们复现这个结果，就等于证明**我们的情绪尺子是准的**；如果 R 段也显著，说明测错了。

## 三、跑起来（VSCode 终端，三步）

在 VSCode 里 `Ctrl + ~` 打开终端，确认在项目根目录（路径末尾是 `Agentic_Research_Challenge`）。

### 第 1 步：先拿 10 期试跑，确认词典读对了

```powershell
python src/data/build_sentiment.py --dict "你的路径/姜富伟词典.xlsx" --limit 10
```

看到这两行才算对：

```
[词典] ... → 积极 3338 / 消极 5890
[抽取] 后端 = pypdf
```

> 词典数量不对（比如只有几十个），说明表格结构没读对——把 xlsx 的两个 sheet 名告诉我，我改读法。
> 如果报 `错误：请用 --dict ...`，说明路径不对，把文件拖进终端就能自动出路径。

### 第 2 步：全量跑（约 2–5 分钟）

```powershell
python src/data/build_sentiment.py --dict "你的路径/姜富伟词典.xlsx"
```

### 第 3 步：看诊断报告

```powershell
code docs/情绪序列诊断.md
```

**验收标准**（只要有一条不满足就停下来）：

| 检查 | 期望 | 不达标怎么办 |
|---|---|---|
| 期数 | **102 行** | 少了说明有 PDF 打不开 |
| `status == ok` | **≥ 98 期** | 不到就贴 `anchor` 列给我，我补分段规则 |
| R 段与 P 段情绪相关系数 | **0.2 ~ 0.6** | >0.8 说明两段没切开；<0 说明切反了 |
| `chars_P` | 多数在 800–6000 | 个别 5000+ 正常（近年报告长） |

跑完会生成两个文件，都要推：
- `data/processed/sentiment.csv`
- `docs/情绪序列诊断.md`

## 四、推到 develop（两种方法，选一种）

> ⚠️ **先记住一件事：绝对不要在项目文件夹里敲 `git add .`**
> `data/raw/` 有 **89.7 MB**（102 份 PDF + 37 个行情 CSV），一旦提交，仓库从 260MB 涨到 350MB+，评审 clone 会很痛苦，而且可能触发大小限制。
> 你的 `.gitignore` 里**没有**忽略 `data/`，所以这个坑是真的会踩。

### 方法 A：网页上传（30 秒，不用装任何东西）✅ 推荐

1. 打开 https://github.com/L3702/Agentic-Research-Challenge-Documents
2. 左上角把分支切到 **`develop`**（默认是 main，**不要提交到 main**）
3. 进入 `data/processed/` 目录 → 右上 **Add file → Upload files**
4. 把 `sentiment.csv` 拖进去 → 下方 Commit changes（信息填 `feat(data): 102 期 MPR 情绪序列（P/R 分段）`）
5. 再重复一次，把代码推到 `src/data/`：
   进入 `src/data/` → Add file → Upload files → 拖 `build_sentiment.py` → Commit

**就这样，不用命令行。** 两次提交，两个文件，都在 develop 上。

### 方法 B：命令行（要装 git，约 5 分钟）

你的机器上**没有装 git**（我查过了），先装：

```powershell
winget install --id Git.Git -e --source winget
```

装完**关掉 VSCode 重新打开**（让 PATH 生效），然后：

```powershell
cd $env:TEMP
git clone -b develop https://github.com/L3702/Agentic-Research-Challenge-Documents.git repo-dev
cd repo-dev
```

把两个文件复制进去（把 `<你的项目路径>` 换成实际路径）：

```powershell
copy "<你的项目路径>\data\processed\sentiment.csv" data\processed\
copy "<你的项目路径>\src\data\build_sentiment.py"  src\data\
```

提交并推送：

```powershell
git add data/processed/sentiment.csv src/data/build_sentiment.py
git commit -m "feat(data): 102 期 MPR 情绪序列（P/R 分段）"
git push origin develop
```

> 为什么用 clone 而不是在你的项目文件夹里 `git init`：你的文件夹里没有 git 历史，直接 init 再 push 会把 89.7MB 的 `data/raw` 一起带上去，而且和远端 develop 的历史对不上。**clone 一个干净的副本，只放两个文件**，最稳。

## 六、跑完之后，下一步是什么

拿到 `sentiment.csv` 就能做 **H1**（证明情绪尺子准）：

```
市场收益（发布后 1 日） ~ z_tone_P + 未预期货币政策操作 + 控制变量
市场收益（发布后 1 日） ~ z_tone_R + 同上          ← 预期不显著
```

这一步过了，再跑 H2（行业交互项）。**顺序不能反**：H1 不过，说明情绪测度有问题，H2 跑了也没意义。

## 七、常见报错对照

| 报错 | 原因 | 处理 |
|---|---|---|
| `ModuleNotFoundError: pypdf` | 没装解析库 | `pip install pypdf`（你队友的环境里已有） |
| `[抽取] 后端 = builtin` | 没找到 pypdf，退回了自带的弱解析器 | 装 pypdf；builtin 只能读 69 期 |
| `[警告] 词典规模偏小` | xlsx 结构没读对 | 把 sheet 名发我 |
| 某期 `status=no_heading` | 该期标题写法特殊 | 把期次发我，加一条规则 |
| `chars_P` 只有几十 | 切到了目录 | 看 `anchor` 列，告诉我期次 |
